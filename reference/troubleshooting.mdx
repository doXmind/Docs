## A file does not appear in the workspace

- Confirm that it is a Markdown Page or supported local Attachment.
- Refresh or reopen the folder after changing files outside doXmind.
- PDF, spreadsheet, and HTML files appear as Attachments; DOCX, PPTX, standalone images, and arbitrary other extensions are not promised as workspace documents.

See [Supported formats](/reference/supported-formats) for the current list.

## An Attachment is read-only

This is expected. PDF, spreadsheet, and HTML files do not mount a doXmind editor. Use **Open Externally** to read or edit the file in its system application, or **Reveal** to locate it in Finder.

Opening an ordinary Attachment does not create a sidecar or rewrite the source.

## Recovery status needs attention

An older PDF or spreadsheet sidecar may be corrupt, from an unsupported or future version, missing a trustworthy source hash, or contain state the isolated recovery bridge cannot apply completely. doXmind reports that conservatively instead of treating the evidence as empty.

Keep the original source, main sidecar, every `.bak`, `.lock`, and `.corrupt-*` file together. Do not rename, combine, replace, migrate, or delete them. If the app offers no attempt—or an attempt fails—the 1.7.8 fallback is eligible only for a schema-v2 PDF or workbook sidecar known to have been created and reopened by doXmind 1.7.8. Follow the exact artifact and isolation steps on the format-specific recovery page. If the evidence version, origin, or schema is unknown or outside that validated scope, stop and preserve the complete evidence set.

## Confirm eligibility before using the 1.7.8 fallback

The current app cannot certify which historical version wrote a sidecar. Seeing a top-level `"version": 2` value confirms only the schema, not that doXmind 1.7.8 created and reopened it. Use the fallback only when your own backup records or recovery notes establish that provenance. If you cannot establish it, stop after preserving the evidence.

To verify the downloaded ZIP on macOS:

1. Open Terminal and type `shasum -a 256 `, including the final space.
2. Drag `doXmind-1.7.8-arm64-mac.zip` from Finder into the Terminal window, then press Return.
3. Continue only if the output is exactly `08aff3948166824089b1a9b5b6964868af442372e3ae240360c3aa78f9c5b9e3` followed by the ZIP path.

Then follow the complete isolation procedure on [PDF Attachments and legacy recovery](/attachments/pdf) or [Spreadsheet Attachments and legacy recovery](/attachments/spreadsheets). A matching ZIP checksum verifies the downloaded app artifact; it does not expand the validated sidecar scope.

## A recovered copy is incomplete or unexpected

- Treat every recovered file as unverified and compare it with the original.
- If both the main sidecar and `.bak` are offered, attempt the other candidate and compare the results.
- PDF recovery refuses unsupported page rotations, source-text mismatches, and text changes that would require silent resizing.
- Spreadsheet recovery refuses state it cannot account for, including saved filters, unsupported structural operations, and UI-only state.
- CSV recovery produces `.xlsx`.
- `.xlsm` recovery produces `.xlsx` without VBA macros.

Do not accept a partial result or delete the evidence set after a successful attempt.

## Hidden sidecars are not visible

In Finder or the macOS Trash, press `Cmd+Shift+.` to show hidden files. A Page sidecar begins with a dot and ends in `.doxmind`. Older Attachment evidence can also include `.bak`, `.lock`, and `.corrupt-*` suffixes.

## External Markdown changes are not visible

Close and reopen the Page or refresh the workspace. When the Markdown source hash differs from the sidecar, doXmind treats the external `.md` text as authoritative and refreshes rich editor state on the next save.

Avoid editing the same Page in doXmind and another application at the same time. The last save can overwrite newer work.

## Still need help?

Email [support@doxmind.com](mailto:support@doxmind.com) and include:

- Your doXmind version from **Settings → About**
- Your macOS version
- The file type and approximate size
- The exact status or error message shown in the app

Do not attach private files unless you intend to share their contents with support. For legacy recovery, preserve the untouched evidence set before sending any copy.
