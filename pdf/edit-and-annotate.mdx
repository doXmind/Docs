---
title: "PDF Attachments and legacy recovery"
description: "Keep PDFs read-only and preserve any historical doXmind recovery evidence."
---

PDF files are read-only **Attachments**. doXmind does not mount a PDF editor, annotate a PDF, extract text for editing, create a new PDF sidecar, or rewrite the source file.

Use **Open Externally** to read or edit the PDF in a system application, and **Reveal** to locate it in Finder.

## Legacy recovery

Older doXmind releases could write PDF editor state beside a source file, for example `.Report.pdf.doxmind`. That data remains user evidence. Current doXmind can inspect legacy artifacts only through an explicit zero-write recovery export.

The recovery report is Markdown containing the exact legacy bytes. It is not a reconstructed or edited PDF, and it never mounts the retired PDF editor.

<Warning>
  Preserve the original PDF, main sidecar, every `.bak`, `.lock`, and `.corrupt-*` artifact together. Do not rename, replace, migrate, or delete any of them before exporting a recovery report.
</Warning>

See [Local storage and legacy sidecars](/workspaces/storage-and-sidecars) and [Troubleshooting](/reference/troubleshooting) for preservation guidance.
