---
title: "Manage Pages and Attachments"
description: "Create and organize local Markdown Pages while preserving read-only Attachments and recovery evidence."
---

The workspace sidebar mirrors real files and folders on your Mac. Its actions differ for editable Pages and read-only Attachments.

## Create and organize

Use the **New** menu to create Pages, folders, or Pages from templates. You can rename or move Pages and folders within the workspace; Page state remains in the Markdown source.

Ordinary Attachment actions are limited to **Open Externally** and **Reveal**. If legacy evidence exists, an Attachment can offer a separate recovery export; it does not mount an editor or change the source.

## Work with external editors

Markdown files remain portable text files, so you can edit them in another app. When doXmind detects a source change, it treats the external Markdown as authoritative.

<Warning>
  Avoid editing the same Page in doXmind and another app at the same time. Resolve any external-edit prompt before continuing.
</Warning>

## Delete and restore

Deleting a Page from doXmind moves its Markdown source to the macOS Trash. Attachment deletion is not offered in doXmind, and there is no separate in-app Trash.

To restore a Page, open the macOS Trash and restore the Markdown file to the intended folder. If legacy artifacts exist, restore the source, main sidecar, every `.bak`, `.lock`, and `.corrupt-*` artifact together before using an explicit recovery export.

## Back up a workspace

Back up the complete folder, including hidden files. Finder can show hidden files with `Cmd+Shift+.`. See [Local storage and legacy sidecars](/workspaces/storage-and-sidecars) for recovery guidance.
